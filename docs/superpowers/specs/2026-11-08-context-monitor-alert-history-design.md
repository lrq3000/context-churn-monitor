Model/window availability comes from the originating request, never an unrelated later baseline. Implementation call: once a turn uses a small or unknown primary model while the filter is enabled, exclude that turn from subsequent alert evaluation and alert averages. A prior live alert issued while the turn was eligible is retained; do not pretend it can be unsent. This conservative mixed-model policy avoids attributing small-model churn to a later large model. Setting changes apply prospectively; changing the eligibility minimum resets the alert-only averaging/recovery state, not recorded monitoring data or history, and does not replay old alerts.

## Shared history and crash recovery

Use a user-wide SQLite store at `~/.local/share/context-churn-monitor/alerts.sqlite` for global alert settings, bounded history and registered backend source locations. Backend-specific replay stores, descriptors and pairings retain their paths. Tests must override the shared alerts path to isolated temporary files; no fixture may change real user alert settings/history.

Persist a bounded threshold-event outbox alongside each backend's monitoring state, in the same local transaction as alert creation. Each event retains stable identity, timestamp, session/project, originating model/context window, metric, value, threshold and trigger kind. Text metadata is bounded and no transcript or credentials belong in history. A stable event key includes source/backend identity, session and alert identity; replay/recovery must not create a new key. Keep at most 100 newest recoverable event records per backend and read bounded batches: older source events cannot belong to the global newest 100 once that source has 100 newer events.

Copy pending events into the shared store with idempotent inserts, prune to the global newest 100 transactionally using a stable timestamp/identity order, then acknowledge locally. A crash after local commit, after global commit or before acknowledgement is safe to replay. Status/title enrichment updates existing retained rows rather than resurrecting evicted events. Restart and history refresh reconcile pending events from registered backend stores, including sources not currently displayed; unavailable/locked sources produce an explicit recovery limitation rather than a false claim of complete history. Register sources before accepting monitored work. Do not scan old alpha databases or reconstruct conversation history.

Record eligible crossings independently of desktop delivery, including missing callback credentials or host/OS suppression. Use honest statuses such as recorded, attempted, host accepted and unconfirmed; host acceptance is not proof of OS display or user reading. Preserve durable single-attempt notification protection. Recovering an outbox row updates history only: it must never automatically resend a notification with an uncertain prior outcome. The 100-entry global cap applies in SQLite and transport/UI, not only to an in-memory view. Bounded text, batches and retention also limit history-related memory use; existing replay-body retention is not changed.
