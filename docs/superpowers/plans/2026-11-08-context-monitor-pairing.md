# Automatic Backend Connection Implementation Plan

> **For agentic workers:** Use `executing-plans` for approved native inline execution, then one fresh-context whole-branch review. Track the checklist and rulings here; preserve artifacts.

**Goal:** Connect the installed monitor automatically to its exact project's healthy backend without mandatory per-worktree manual pairing.

**Architecture:** Add an indexed descriptor-path registry through the already-open user-wide SQLite handle. Backend startup registers its descriptor; GUI bridge discovery reuses strict descriptor/health validation and leaves explicit manual overrides authoritative.

**Tech Stack:** Existing TypeScript, Node/Bun SQLite, OpenCode/OpenChamber SDKs, Node tests and Chrome Playwright; no new dependencies or resident processes.

**Spec:** `docs/superpowers/specs/2026-11-08-context-monitor-pairing-design.md`

## Global constraints

- Keep existing per-initialized-project/worktree backend lifecycle. No resource-redesign work or later brainstorming.
- Exact normalized project identity only; no port/filesystem scans, guessed credentials or implicit manual-override fallback.
- Registry lives in the existing shared `alerts.sqlite` handle, containing only directory/path metadata. Automatic discovery does not write the pairing file.
- At most nine indexed candidates read, reject more than eight, at most eight concurrent health checks with 2500ms deadlines; reject multiple healthy candidates. No uncertain POST retries.
- Preserve alerts/history/replay and prior manual/legacy pairing behavior. Tests isolate SQLite/artifacts.
- Approved release 0.3.1 / 2026-11-08; creation 2026-11-03 and unchanged skill/config records preserved. Installed backup/refresh and squash/push of main plus fix branch approved; no cleanup.

## Review focus

- Windows aliases and custom data roots must resolve the correct project without rewriting existing descriptor identities.
- Two live backend instances must not be selected arbitrarily; stale paths must not leak credentials to a reused listener.
- A failed registration must not leave a live orphan listener or alter alert history/settings.
- An explicit but broken manual override must remain authoritative; an uncertain write must never be replayed by discovery.
- Native UI proof must exercise real service/backend data, not merely render the static shell or mask connection errors.
