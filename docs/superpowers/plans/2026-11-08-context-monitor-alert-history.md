# Global Alert Controls and History Implementation Plan

> **For agentic workers:** Use `executing-plans` for native inline execution with one independent final whole-branch review. Steps use checkbox syntax; the ledger below is authoritative on resume.

**Goal:** Make existing alert thresholds editable globally, filter out small-context turns, and provide a crash-recoverable global last-100 history with session navigation.

**Architecture:** Keep request accounting unchanged and isolate model-window eligibility/alert averages in bounded alert-policy state. Write threshold events into the local monitoring transaction, then reconcile them idempotently into one user-wide SQLite settings/history store. The authenticated GUI service exposes global controls/history independently of project pairing; session navigation uses the existing SDK capability.

**Tech Stack:** Existing TypeScript, SQLite on Node/Bun, OpenCode plugin SDK 2.2.5, OpenChamber SDK 2.6.0, Node tests and Playwright Chrome. No new dependency required.

**Spec:** `docs/superpowers/specs/2026-11-08-context-monitor-alert-history-design.md`

## Global constraints

- Preserve the existing growth-in-percentage-points and compaction metrics. Do not add occupancy detection.
- Minimum context window defaults to 32000 tokens, inclusive; zero disables the filter, unknown capacity fails eligibility when enabled. Ordinary monitoring continues for ineligible turns.
- Global history contains at most 100 persisted records across projects, with bounded metadata and reads; local recovery records are bounded to 100 per backend.
- No old alpha history import. New-event outbox commit, global insertion and local acknowledgement must tolerate restart, duplicate replay and concurrent writers without uncertain notification resend.
- Shared store: `~/.local/share/context-churn-monitor/alerts.sqlite`; fixture overrides must isolate tests. Preserve replay stores, descriptors and pairings.
- Version backend/portable/UI at 0.3.0, updated 2026-11-08; preserve creation and unchanged skill metadata.
- Use local commits, one final reviewer and the approved installed refresh. No merge, push or destructive cleanup.

## Review focus

- A small/unknown model followed by a large model in the same turn must not trigger on the small model's accumulated churn; earlier legitimate live alerts must not disappear.
- Excluded turns and eligibility-setting changes must not poison alert averages, consume eligible-turn cooldowns or fabricate recovery.
- A crash at any handoff boundary must recover the retained event exactly once in history without repeating an uncertain desktop notification.
- Concurrent source processes, old pending events and late status enrichment must leave no more than 100 global entries and must not resurrect evicted rows.
- Global controls/history must work without pairing or a selected session; refresh/eviction/session changes must never navigate to a different row or erase actionable errors.
